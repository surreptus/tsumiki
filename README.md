# 積み木 (Tsumiki) — Functional Japanese Grammar Guide

A Japanese grammar reference that models verb and adjective morphology as **function composition**.
Every verb has a few *stem functions*; every grammatical suffix is a function that takes one specific
stem and returns a typed result (verb, い-adjective, な-adjective, noun, or closed clause). Long forms are
compositions, and every intermediate form has a type:

```
食べさせられたくなかった = past(neg(tai(passive(causative(食べる)))))
```

Built with [Astro](https://astro.build) + [Starlight](https://starlight.astro.build), MDX content,
content collections validated with Zod, and Pagefind search.

## Commands

```bash
npm install
npm run dev              # dev server (search is disabled here, see below)
npm run build            # type-check (astro check) + build + index search
npm run preview          # serve the production build
npm run check:links      # after a build: every internal link and #anchor resolves
npm run check:a11y       # after a build: axe over every page, dark and light (needs a browser)
npm test                 # Vitest: the conjugation engine and the data
```

> **Search only works after a build.** Starlight's Pagefind index is generated by `npm run build`,
> so the search box does nothing under `npm run dev`. Use `npm run build && npm run preview` to try it.

## How it fits together

| Path | What |
| --- | --- |
| `src/data/stems/*.json` | One stem function per file, with its rule per verb class (ichidan, godan by final kana, する, 来る, adjectives) |
| `src/data/suffixes/<attach point>/*.json` | One suffix per file: what it attaches to, input/output types, meaning, examples |
| `src/data/verbs.json`, `predicates.json` | Sample lexicon: verbs, and い-/な-adjectives and nouns |
| `src/data/irregulars.json` | Every exception to the stem rules |
| `src/lib/schemas.ts` | Zod schemas for all of the above (shared by collections and the engine) |
| `src/lib/conjugate.ts` | Pure TypeScript engine: `stem`, `apply`, `compose` |
| `src/content.config.ts` | Content collections: `docs`, `stems`, `suffixes`, `verbs`, `predicates`, `irregulars` |
| `src/components/` | `StemTable`, `Derivation`, `SuffixTable` (build-time Astro), `Conjugator` (the one hydrated Preact island) |

See [PLAN.md](PLAN.md) for the content inventory and what is planned for Phases 2 and 3.

### Adding a suffix

1. Add `src/data/suffixes/<attaches_to>/<id>.json` (the folder must equal `attaches_to`).
2. `node scripts/gen-suffix-pages.mjs` writes the page stub (it never overwrites existing pages).
3. `npm test` checks the data against the schemas, cross-references and example readings.

## Accessibility

Target: WCAG 2.2 level AA. `npm run check:a11y` runs axe-core (WCAG 2.0, 2.1 and 2.2 A/AA plus best-practice
rules) over every page in both themes, and the deploy fails on any violation. Checked by hand for reflow at 320px, reduced motion,
visible focus, and information that is not conveyed by colour alone. Automated tools find only part of the
issues, so this is not a certification: a screen-reader pass and keyboard walkthrough are still worth doing.
Colours are Dracula (dark) and Alucard (light) with text variants adjusted for contrast, see `src/styles/custom.css`.
The check needs a browser: run `npx playwright-core install chromium` once.

## Deploying to GitHub Pages

The site is configured for `https://surreptus.github.io/tsumiki/` (see `site` and `base` in `astro.config.mjs`). If the repository has a different name, or the site moves to a custom domain, build with `SITE` and `BASE` set, for example `SITE=https://example.com BASE=/ npm run build`.

To publish: push to `main` and, in the repository settings under Pages, set the source to "GitHub Actions". `.github/workflows/deploy.yml` runs the tests, builds, and deploys.
